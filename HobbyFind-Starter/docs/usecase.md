# 유스케이스 명세서: UC-03 사용자 상세 프로필 조회

## 1. 개요 및 기본 정보

- 유스케이스 ID: UC-03
- 유스케이스명: 사용자 상세 프로필 및 취미 컬렉션 조회
- 액터: 비로그인 방문자(Visitor), 시스템(System)
- 목적: 메인 또는 카테고리 페이지에서 특정 사용자의 프로필 카드를 클릭하여 해당 사용자의 상세 소개, 활동 스탯, 수집/자랑한 취미 활동 목록을 열람한다.

## 2. 액터 정의

| 액터 | 설명 | 역할 |
|---|---|---|
| Visitor | 비로그인 사용자 | 루트 페이지 또는 카테고리 페이지에서 프로필을 탐색하고 상세 페이지를 조회한다. |
| System | 애플리케이션 시스템 | 사용자 식별 기반 상세 데이터를 조회하고 화면을 렌더링한다. |

## 3. 사전 조건 및 사후 조건

### 3.1 사전 조건 (Preconditions)

- 시스템에 등록된 사용자 프로필 데이터가 존재해야 한다.
- 방문자는 루트 페이지(`/`) 또는 카테고리 페이지(`/category/[type]`)에서 특정 사용자 프로필 카드가 노출되어 있어야 한다.
- 카드에 연결된 사용자 식별자(`userId`)가 유효해야 한다.

### 3.2 사후 조건 (Postconditions)

- 선택한 사용자의 상세 정보와 취미 컬렉션 그리드가 포함된 `/profile/[userId]` 페이지가 화면에 정상 렌더링된다.
- 방문자는 해당 사용자의 소개, 활동 스탯, 취미 컬렉션을 확인할 수 있다.

## 4. 상세 Use Case 시나리오

### 4.1 기본 시나리오

| 단계 | 주체 | 수행 동작 |
|---|---|---|
| 1 | Visitor | 메인 또는 카테고리 페이지에서 특정 프로필 카드(예: `서윤` 프로필 카드)의 전체 영역 또는 `View profile` 링크를 클릭한다. |
| 2 | System | 클릭된 카드의 사용자 식별자(`userId`)를 파악하고 상세 프로필 경로(`/profile/[userId]`)로 페이지 전환을 요청한다. |
| 3 | System | 해당 `userId`에 해당하는 프로필 상세 정보(이름, 소개글, 별점, 위치, 활동 스탯) 및 사용자가 등록한 취미 카드 목록을 조회한다. |
| 4 | System | 상단 프로필 헤더(배너, 아바타, 대표 태그, 스탯)를 구성한다. |
| 5 | System | 해당 사용자가 등록한 취미 카드들을 그리드 레이아웃으로 화면 하단에 렌더링한다. |
| 6 | Visitor | 사용자의 상세 소개글과 스탯을 확인하고, 하단 컬렉션 그리드를 통해 세부 취미 활동 내역을 탐색한다. |

## 5. 주요 단계 및 이벤트 흐름

### 5.1 메인 플로우

1. 방문자가 메인 또는 카테고리 페이지에서 특정 사용자 카드를 선택한다.
2. 시스템은 해당 카드의 `userId`를 기반으로 상세 페이지를 요청한다.
3. 시스템은 사용자 기본정보와 취미 활동 데이터를 조회한다.
4. 시스템은 상단 프로필 섹션을 렌더링한다.
5. 시스템은 사용자별 취미 컬렉션 카드 그리드를 렌더링한다.
6. 방문자는 상세 프로필을 확인하고 취미 활동을 탐색한다.

### 5.2 화면 구성 예시

| 영역 | 설명 |
|---|---|
| Header | 상단 로고/네비게이션 및 카테고리 필터 유지 |
| Profile Header | 배너, 아바타, 이름, 태그, 별점, 위치, 소개글 |
| Stat Area | 수집한 기록, 누적 시간, 카테고리 정보 등 |
| Filter Tabs | 전체, 특정 취미 태그별 필터 |
| Hobby Grid | 사용자 취미 자랑 카드 목록 |

## 6. 대체 흐름 및 엣지 케이스

### 6.1 대체 흐름: 취미 태그 필터 선택

- 상황: 방문자가 상세 프로필 페이지 내에서 특정 취미 태그 버튼(예: `[조깅/러닝]`)을 클릭한다.
- 시스템 동작: 전체 컬렉션 중 해당 취미 태그에 해당하는 활동 카드만 재정렬하여 즉시 보여준다.
- 결과: 방문자는 특정 취미에 집중된 활동 기록을 빠르게 탐색할 수 있다.

### 6.2 엣지 케이스: 등록된 취미 카드가 없는 사용자

- 상황: 프로필은 존재하지만 수집/자랑한 취미 활동 카드가 0건인 경우.
- 시스템 동작: 그리드 영역에 "아직 등록된 취미 활동이 없습니다." 안내문과 함께 Empty State UI를 노출한다.
- 결과: 사용자에게 비어 있는 상태를 명확하게 전달하고 오류로 오인하지 않게 한다.

### 6.3 엣지 케이스: 유효하지 않은 userId

- 상황: 존재하지 않는 `userId`로 접근하는 경우.
- 시스템 동작: 사용자 정보 조회 실패 시 Not Found 상태 화면을 렌더링한다.
- 결과: 방문자는 잘못된 접근임을 인지하고 안전하게 이전 페이지로 복귀할 수 있다.

## 7. 비즈니스 규칙 및 제약사항

| 규칙 | 내용 |
|---|---|
| 접근 조건 | 비로그인 사용자도 조회 가능해야 한다. |
| 데이터 범위 | 프로필 상세 페이지는 해당 사용자 정보만 표시해야 한다. |
| 취미 범위 | 취미 목록은 고정 카테고리와 하위 항목을 따라야 한다. |
| 조회 방식 | 카드 클릭 시 사용자 식별자를 기반으로 직접 상세 페이지로 이동해야 한다. |
| 필터 범위 | 상세 페이지 필터는 같은 사용자가 보유한 취미 범위 내에서만 동작해야 한다. |
| UI 제한 | 추가 기능(좋아요, 댓글, 팔로우)은 본 유스케이스 범위를 벗어난다. |

## 8. 데이터 요구사항 및 데이터 흐름

### 8.1 데이터 구조 예시

```ts
{
  userId: 1,
  name: '서윤',
  category: '운동형',
  title: '주말 러너',
  bio: '도시를 한 바퀴 돌며 매주 새 코스를 찾는 것을 즐겨요.',
  location: '서울',
  rating: 4.9,
  stats: {
    totalActivities: 18,
    totalHours: 142,
    favoriteTags: ['조깅/러닝', '자전거']
  },
  hobbyCollection: [
    {
      id: 'hobby-01',
      title: '아침 러닝 기록',
      hobbyTag: '조깅/러닝',
      date: '2026-08-01',
      duration: '45분',
      description: '한강변 러닝 루트 완주'
    }
  ]
}
```

### 8.2 데이터 흐름

1. 프로필 카드 클릭 → `userId` 전달
2. 상세 페이지 로드 → 사용자 정보 조회
3. 활동 목록 조회 → 취미 컬렉션 렌더링
4. 취미 태그 선택 → 목록 필터링
5. Empty State 처리 → 데이터가 없을 때 안내 렌더링

## 9. UI 고려사항

- 프로필 상세 페이지는 루트 페이지와 일관된 스타일을 유지해야 한다.
- 상단 배너와 프로필 아바타는 카드형 리스트와 구분되는 강조 구조를 가져야 한다.
- 취미 태그 버튼은 클릭 가능한 상태를 시각적으로 명확하게 표현해야 한다.
- 컬렉션 카드와 상세 페이지 헤더는 여백과 간격을 일관되게 유지한다.
- 모바일 환경에서는 1열 레이아웃, 데스크톱에서는 2열 이상 그리드로 자연스럽게 전환한다.

## 10. 예외 처리 절차

| 예외 상황 | 처리 방식 |
|---|---|
| 잘못된 `userId` | 빈 상태 또는 Not Found 페이지 렌더링 |
| 데이터 로딩 실패 | 기본 메시지 표시 및 재시도 가능하도록 상태 처리 |
| 취미 컬렉션이 비어 있음 | Empty State 메시지 표시 |
| 필터가 일치하는 카드가 없음 | "조건에 맞는 활동이 없습니다" 안내 렌더링 |

## 11. 보안 및 개인정보 고려사항

- 비로그인 사용자가 조회할 수 있는 정보는 공개 범위로 제한되어야 한다.
- 사용자 프로필은 개인 정보가 최소화된 형태로만 노출되어야 한다.
- 민감 정보는 본 유스케이스에서 다루지 않으며, 공개 가능한 정보만 렌더링한다.
- 상세 페이지의 데이터 접근은 사용자 식별 기반 조회만 허용하고, 잘못된 접근 시 안전하게 차단한다.

## 12. 요구사항 요약

- 비로그인 사용자는 카드 클릭을 통해 특정 사용자 상세 정보를 조회할 수 있어야 한다.
- 상세 페이지는 프로필 소개, 스탯, 취미 컬렉션을 모두 포함해야 한다.
- 취미 태그 기반 필터와 Empty State 처리가 포함되어야 한다.
- 기존 루트 페이지/카테고리 페이지와 일관된 UI 톤을 유지해야 한다.

## 13. 구현 참고 포인트

- 라우트: `/profile/[userId]`
- 기준 컴포넌트: 프로필 헤더, 활동 스탯, 태그 필터, 컬렉션 카드 그리드
- 사용자 상세 데이터는 정적 구조 또는 퍼블릭 데이터 소스로 구성 가능
- 현재 기능 범위를 벗어나는 댓글/좋아요/팔로우/메시지 기능은 포함하지 않는다.
