다음 정보를 바탕으로 PRD(Product Requirements Document)를 작성해줘
[서비스 개요]
- 서비스명: HobbyQuest
- 서비스 타입: 웹서비스
- 이용 조건: 비로그인 사용자도 이용 가능
- 목적: 내가 만든/경험한 취미 활동을 수집하고 자랑하는 사이트
- 추가 기능 제안은 포함하지 말 것

[페이지 구성]
1. 루트페이지
 - Top Bar: 로고 / 카테고리 필터(운동형, 수집형, 예술형)
 - Hero 섹션: 사이트 소개 문구
 - 메인 콘텐츠: 그리드 형식으로 사용자 프로필 나열, 대분류(운동형·수집형·예술형) 필터 가능
 - 카테고리 필터 선택 시 → 해당 카테고리에 속하는 취미를 가진 사용자들만 모아 보여주는 카테고리별 전용 페이지
(운동형 페이지 / 수집형 페이지 / 예술형 페이지)

2. 카테고리별 페이지
 - 페이지 상단에 선택된 사용자명과 간단한 사용자 취미 프로필 소개 문구
 - 해당 카테고리에 속한 사용자 프로필만 그리드 형태로 나열

[PRD에 반드시 포함할 항목]
1. 제품 상세 설명 (Detailed Product Description): 서비스 설명과 핵심 목표
2. 참고 서비스 및 근거 (Reference Services with Detailed Rationale)
3. 핵심 기능 및 사양 (CoreFeatures and Specifications)
4. 사용자 페르소나 및 시나리오 (User Persona and Scenarios)
5. 기술 스택 추천 (Technical Stack Recommendations): Next.js
6. 제한사항(Limitations) — 언급한 페이지 구성 외에 추가 기능 제안은 포함하지 않음

[작성 스타일]
- 명확하고 간결하게
- 불필요한 기능 제안은 제외
- 표와 리스트를 적극 활용
- 실제 개발자가 참고할 수 있을 정도로 구체적으로 작성

[취미 리스트]
- 취미 목록은 아래와 같이 고정되며, 변경·확장하지 않는다.
 • 운동형: 조깅/러닝, 요가, 수영, 자전거, 클라이밍, 댄스
 • 수집형: LP (바이닐) & 음반 수집, 스페셜티 원두 & 와인/위스키, 식물 (희귀 식물/토분), 스니커즈 (한정판 운동화), 레고 & 피규어
 • 예술형: 그림 그리기, 악기 연주, 요리, 서예, 도자기 만들기, 단편 글쓰기
